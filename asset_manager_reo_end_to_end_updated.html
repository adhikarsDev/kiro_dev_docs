How the Asset Manager Starts the Day

The attached Connect on REO Control Tower transcript describes a chronological portfolio view combined with an exception-first command center.

1. Portfolio position

  • Show the Asset Manager's portfolio and task list in lifecycle order.
  • Make the current position of each asset visible, from broker assignment and occupancy through marketing, offers and closing.
  • Keep the portfolio view live enough to surface process gaps without waiting for a periodic exception report.

2. Problem assets first

  • The first working window should show every file that has become an exception.
  • Examples explicitly discussed include missing valuations, delayed trash-outs, overdue investor approvals and stalled offer decisions.
  • These items should be visually prominent so the Asset Manager can resolve them immediately.

3. Actionables next

  • A separate actionable view should show work that is ready for a decision or approval, such as offers to accept and trash-out bids to approve.
  • After an action is taken, the system should track elapsed time and move the file into the exception view if it remains unresolved beyond its expected follow-up point.

4. Communication assist

  • Use repeatable templates for routine vendor and investor follow-ups.
  • Present a draft communication for user review and sending rather than requiring the Asset Manager to assemble the same data and message repeatedly.
  • Track responses and keep the associated file visible until the issue is resolved.

1. Pre-Marketing Readiness

Establish that the property is ready to enter the market process.

Asset Manager work

  • Review the assigned property and open workflow tasks.
  • Confirm readiness prerequisites, including that the property is secured.
  • Verify initial services are complete. The transcript explicitly calls out cleanout and trash removal as items that must be represented in the readiness gate.
  • Confirm that the property is appropriately assigned to a broker and correctly established in Equator.
  • Order the occupancy task and follow up when occupancy results are due.
  • If occupied, route the file to the eviction team and maintain periodic follow-up on attorney communication, inspections and updated values during a prolonged eviction.
  • If vacant, order services through Triple R and ensure AFS re-secures the property.
  • Follow up on cleanout, initial services and valuation delivery on a recurring basis. The attached transcript proposes approximately every 72 hours for these pre-marketing checks.
  • Review lockbox and other pre-listing information where applicable.

Decision / exit gate

  • Ready for valuation and marketing-plan completion.
  • If prerequisites are incomplete, hold the marketing path and resolve the outstanding item.

Evidence / data

  • Property and workflow status in Equator.
  • Field-services status may be surfaced from Palladium or Altisource field services.
  • Readiness checks and resulting exceptions.

Controls

  • Investor/client-specific rules must be configurable.
  • Exceptions and SLA breaches should remain visible to the Asset Manager.
  • Human review remains required where rules are absent or authority is unclear.

2. Valuation and Value Reconciliation

Assemble the value picture that will drive marketing strategy and pricing.

Asset Manager work

  • Retrieve available property valuations and property facts.
  • Compare the valuation inputs and resolve inconsistencies.
  • Use the reconciled value as an input to initial list-price and marketing strategy.
  • Perform independent research rather than relying only on the automated comparison of two values.
  • Follow up with Triple R and the BPO vendor when values are outstanding.

Decision / routing

  • Resolve the marketing value when valuations differ.
  • The Control Tower presentation referenced a specific judgment point when two valuations differ by at least 5%.
  • Route for approval when the final strategy is outside delegated authority.

Evidence / data

  • Initial/current BPO values, vendor valuations and appraisal data when present.
  • Investor rulebook and delegated-authority thresholds.
  • Documented reasoning for the reconciled value.

Exceptions

  • Missing, stale or conflicting valuation inputs.
  • Investor-specific treatment not represented in the configured rules.

3. Complete Marketing Plan (CMP)

Turn readiness and valuation into an approved entry-to-market plan.

Asset Manager work

  • Retrieve property details and confirm prerequisites.
  • Reconcile valuations.
  • Apply investor rules and assess the marketing strategy.
  • Calculate the initial list price and, where applicable, auction reserve / starting-bid values.
  • Select the listing type and commission structure.
  • Complete the marketing-plan form and submit the approved plan to Equator.

Decision / approval

  • Approve, modify or reject the proposed strategy.
  • Determine whether the action is inside delegated authority or requires Asset Manager/client/investor approval.
  • Where investor rules are not available, route to human review.

Key commercial inputs

  • Reconciled valuation.
  • Initial list price and marketing sequence.
  • Listing type, listing-agent commission, selling-agent commission, referral/other fees and incentives as configured.
  • Selected commission values flow from the most recent marketing plan to the listing channel.

Controls

  • Rules and thresholds must be changeable with validation and audit history.
  • Asset Managers must be able to intervene or manually trigger urgent work.
  • Approved updates are submitted under the authenticated user's Equator session.

4. Listing and Auction Activation

Publish the approved property strategy and monitor the active sales channel.

Asset Manager work

  • Confirm the approved SRP/listing package and property data are transmitted to Hubzu for the third-party sale listing.
  • Monitor listing acknowledgement and Hubzu's data-quality checks.
  • Track auction/listing status and resolve rejected or incomplete listing data.

TLB auction path

  • A supply-auction-status task remains open during the auction cycle.
  • At auction end, Hubzu returns successful or unsuccessful status.
  • An unsuccessful cycle may trigger the next reserve-price activity, subject to conditions such as agent or list-price changes.
  • A successful/finalized auction triggers third-party sale results and offer intake.

Traditional / non-cycle path

  • For a traditional listing path, offers can continue to flow through the sale-results workflow without the same auction-cycle status pattern.
  • If listed with a local broker instead of Hubzu, offers can enter OMS with the listing agent recorded as the source.

Monitor

  • Listing acknowledgement failures.
  • No bids or bids below reserve.
  • Property, agent or list-price changes that interrupt automated progression.

5. On-Market Monitoring and Review Marketing Plan (RMP)

Keep pricing and marketing aligned with elapsed market time, buyer interest and investor rules.

Asset Manager work

  • Check whether the property is eligible and due for review.
  • Gather current property, investor, pricing and market-interest information.
  • Maintain weekly touchpoints with the broker, review property work in progress and assess current market conditions and Hubzu analytics.
  • Use a recurring two-week review point to evaluate whether a reduction case should begin, according to the operating approach discussed in the attached transcript.
  • Check active offers and pending approvals before reducing price.
  • Review the proposed reduction and resulting list price.
  • Approve, override or route the change and submit it to Equator.

Documented SPSRU example

  • The transcript describes an 8% reduction every 28 days.
  • This is an example of a configured investor rule, not a universal policy for every client or investor.
  • Approval routing must remain within delegated authority.

Downstream actions

  • Broker signs the reduction.
  • Updated MLS evidence is uploaded.
  • E-sign status and timestamps were discussed as milestones that could be monitored.

Controls

  • Do not apply a reduction mechanically when an active offer or approval is pending.
  • Log the decision, calculation, authority path and any override.
  • Prepare a comprehensive investor reduction request with supporting research and analytics.
  • When an initial listing or reduction request remains unanswered, begin the follow-up sequence described in the meeting: escalation on day three followed by daily investor and management follow-up while it remains outstanding.

6. Offer Intake, Comparison and Disposition

Turn bids and offers into a defensible disposition decision.

Offer intake

  • Auction bids are received from Hubzu after the auction result workflow opens.
  • Multiple bids from the same submitter are linked as bid instances under the same offer, with the latest instance visible.
  • Post-auction bids arrive as backup offers and are held while in-auction offers are addressed.
  • Local-broker offers can arrive through OMS in real time.

Asset Manager analysis

  • Compare gross offer, net offer, list-price relationship, FMV relationship, financing, concessions/credits, commissions and other selling costs.
  • Apply investor approval and delegated-authority rules.
  • Consider timing, representation and the status of competing offers.
  • Use current analytics and relevant historical offers when preparing the acceptance recommendation.
  • Draft the investor request needed to approve acceptance or a counter.
  • Once investor authority is received, make acceptance/counter and contract initiation a top-priority same-day actionable.

Permitted outcomes

  • Accept.
  • Counter / negotiate.
  • Request highest and best.
  • Route for approval.
  • Reject and relist, reject all, or hold where supported by the workflow and guidelines.

Important caveats

  • Backup offers should not be treated as immediately actionable while in-auction offers remain unresolved, based on the process described in the transcript.
  • Net-offer calculations vary by workstation/investor configuration. The meeting explicitly rejected a single assumed commission formula.
  • Seller-paid concessions or credits reduce the net amount to the seller.

7. Accepted Offer and Contract Handoff

Move the selected offer into the contract and closing track.

Asset Manager work

  • Finalize the selected offer action and required approval.
  • Ensure the approved action is written to Equator through the controlled workflow.
  • Confirm closing tasks are opened for the accepted offer.
  • Monitor title work and other parallel items shown in the pipeline.

Human control point

  • In the supervised model described, recommendations do not become system-of-record actions until a human approves them.
  • The Asset Manager may approve, modify or reject the recommendation.
  • User identity, permissions and attribution carry through the Equator session.

Evidence

  • Offer worksheet and approval path.
  • Accepted terms, net economics and closing target.
  • Audit record of the recommendation and human action.

Transcript gap

  • The retrieved meetings do not fully enumerate contract-package generation, buyer execution, earnest-money handling, title-clearance owners or every approval between acceptance and closing.

8. Closing Management

Track the transaction to settlement and keep financial and status data aligned.

Asset Manager work

  • Monitor the closing date, closing tasks, title track, documents and exceptions.
  • Coordinate or follow up on delays and amended closing activity.
  • Ensure closing costs, seller credits/concessions and other expenses are reflected in the net proceeds.
  • Review final closing data before the file is cleared.

Documented data point

  • For SPS, the meetings discuss recording total closing per diem paid by the buyer when the buyer causes a delay past the agreed closing date.
  • The per-day amount is established during the offer process; the total paid at closing must be captured.
  • ResWare was identified as the source where that total is tracked, with a proposed future automation into Equator.

Systems / records

Equator / eqSellerResWareTitle trackClosing contractFinal HUD / settlement data

Exceptions

  • Buyer-caused delay and per-diem amounts.
  • Changed closing dates and amended closing tasks.
  • Missing final documents or mismatched financial data.
  • The meetings state that the closing agent had not yet been fully developed at that time.

9. Closed / Sold Status and File Clearance

Confirm settlement completion, final data capture and closure of the property workflow.

Asset Manager outcome

  • Confirm the sale completed and the pipeline moved through full execution of sale to closed status.
  • Confirm final funds/settlement information and closing data are recorded.
  • Resolve remaining pending actions or red flags before the property is treated as cleared.
  • Complete or verify the closed-file task.

Closeout evidence

  • Closing date and sale status.
  • Final HUD / settlement information.
  • Closing costs, seller concessions/credits and delay-related amounts.
  • Closed-file workflow status and audit history.

Operational view

  • Track average time to close, aging, SLA compliance and properties blocked by pending actions.
  • Retain reports, user actions, approvals, overrides and agent recommendations as an evidence trail.

Validation needed

  • Final operational sign-off criteria, reconciliation owner, archival requirements and any investor-specific post-sale reporting were not fully defined in the retrieved transcripts.

Explicit Escalation Signals Discussed in the Attached Meeting

These are examples stated in the transcript. They should be validated against client/investor rules before being configured as universal SLAs.

Values missing

  • At 5 days in the system without a value, surface the affected files and offer a drafted vendor follow-up.
  • At 10 days in the portfolio without values, show a prominent escalation.

Initial services delayed

  • Use recurring pre-marketing follow-ups, proposed at roughly 72-hour intervals.
  • At 15 days in the portfolio without trash-out completion, show a prominent exception.

Investor response delayed

  • For an outstanding initial listing or reduction request, begin escalation on day three.
  • Continue daily follow-up with the investor and management while the decision remains outstanding.

On-market aging

  • The meeting used 30 days on market without an accepted offer as a signal to process a reduction.
  • This signal complements, and does not replace, investor-specific pricing and approval rules.

Communication and Follow-Up Playbook

Vendor follow-up

  • Identify all files in the same exception category.
  • Pre-build a consistent message asking for status on debris removal, lawn service, property safety/readiness or missing values.
  • Allow the Asset Manager to review and send the grouped communications.
  • Track incoming responses against the property.

Investor follow-up

  • Include the request type, supporting data and elapsed time.
  • Use a professional, direct reminder that the approval remains outstanding.
  • Maintain consistent messaging through configurable templates.

Decision support

  • Separate administrative time-saving from actions that actually advance the property.
  • CMP automation mainly reduces administrative work; offer-acceptance support also advances the property toward contract and closing.

Continuous monitoring

  • Use an overarching portfolio monitor to surface files that fall into gaps.
  • Use specialized agents or workflow tools to help resolve each surfaced issue.
  • Return unresolved items to the exception view automatically when their follow-up point is reached.

Cross-Cutting Asset Manager Operating Model

Daily control
Work the assigned property/task queue, monitor pipeline phase, aging, SLA breaches, exceptions, active offers, closings and blocked properties.
Rule application
Apply client/investor guidelines and delegated authority. Where rules are missing, unclear or outside authority, route rather than infer.
Decision pattern
Read facts → calculate gates/formulas → evaluate options → validate output → present recommendation → human approves/modifies/rejects → approved action is written to Equator.
Evidence
Preserve data inputs, calculations, selected guideline, recommendation, reasoning, user action, override and system-of-record result.
